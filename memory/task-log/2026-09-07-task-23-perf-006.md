## 理解与边界

第一阶段完成 `assets/inject/renderer-inject.js` 的职责分组与确定性单 IIFE 构建入口，保持 Rust `include_str!` 路径、浏览器运行时私有作用域、初始化顺序和现有字符串契约不变。只新增注入源码模块/构建脚本、manager 构建命令、本任务大纲登记和任务日志；不修改 IPC、Rust 资产读取逻辑、注入函数体、凭据或既有未提交文件。

## 调研与复用

- 官方 esbuild API 资料确认浏览器 bundle 的 IIFE 输出可保持顶层变量不泄漏，并且 ESM 入口是 tree-shaking 的基础；本机没有 `node_modules`，仓库规则也不允许为本轮擅自安装依赖，因此第一阶段采用 Node 内置 API 的无运行时依赖 lexical-fragment bundler。
- 复用既有 `renderer-inject.js` 作为唯一行为源，按原始行边界拆分为 `core`、`dom`、`session`、`patch`、`bridge`、`features`、`entry` 目录；模块顺序单独登记在 `src/module-order.mjs`，避免为“模块化”引入第二套运行时状态。
- 冲突裁决：用户要求透明等价与等待架构师审查优先于“一次性重写为显式 ESM 依赖图”；因此先保留共享词法闭包，显式依赖注入/真正 import-export 边界列为审查议题，不冒充已完成。
