# Renderer injection source modules

`renderer-inject.js` is a generated browser artifact. Rust continues to read
that exact path through `include_str!` in `crates/codex-plus-core/src/assets.rs`.

The source is split into ordered lexical modules so the first refactor phase
does not change the shared private scope of the injection runtime. This is
deliberate: many existing functions communicate through private `const`, `let`
and function declarations, so introducing runtime ESM boundaries in one pass
would change initialization and retry behavior. The build script assembles the
modules into one self-contained IIFE and contains no runtime dependency.

Run from `apps/codex-plus-manager`:

```text
npm run inject:build
npm run inject:check
```

Keep `module-order.mjs` order stable. A module may be edited in place, but a
module move is an architectural change because it can alter lexical
initialization order. `inject:check` compares the generated bytes with the
checked-in artifact and is intended for local and CI contract checks.
